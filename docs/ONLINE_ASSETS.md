# 在线封面与歌词

本轮基于 `3383da0`，源码版本保持 `0.3.4`。发布使用后续独立版本提交；已有标签保留。

## 使用方式

### 手动查找与纠正

歌曲表格或队列的更多菜单提供“查找在线封面…”和“查找在线歌词…”。专辑详情提供封面入口；正在播放页的更多菜单和空歌词区域也可以打开检索。

进入窗口后，确认或修改歌名、艺术家与专辑，点击“查找”。这些编辑只影响查询，音频文件标签保持原样。歌词支持 LRCLIB、QQ 音乐与网易云音乐；封面支持 MusicBrainz / Cover Art Archive、QQ 音乐、网易云音乐和 Deezer。窗口默认“全部来源”，可指定单个来源。详细说明通过“来源与隐私”按需展开。

候选行展示作品、艺术家、版本或时长等信息。点击行查看歌词纯文本或经过本地解码的封面预览，再点击“应用并关闭”。封面先下载到预览区，确认后才绑定；预览失败会保留明确错误状态。

默认只应用于当前歌曲。有可靠专辑身份时，可以勾选应用到当前专辑；范围同时要求相同目录、专辑名和专辑艺术家，专辑艺术家缺失时采用歌曲艺术家。无标签单曲保持独立身份，“未知专辑”聚合页继续采用原来的默认封面。信息不足时可手动修订搜索词。

“导入本地…”支持 JPEG、PNG、当前 Qt 图像插件提供的 WebP，以及 UTF-8 / UTF-16 BOM 的 LRC/TXT。后续逐字高亮迭代同时加入增强 LRC、歌词 TTML、明文 YRC/QRC 的受限解析与导入，范围见 [WORD_TIMED_LYRICS.md](WORD_TIMED_LYRICS.md)。它们与在线选择共用应用资料存储。“来源页面”由用户点击后在浏览器打开。

“恢复默认…”恢复本地优先，同时保存此项的自动补全停用标记，避免用户刚撤销的资料再次自动出现。以后仍可手动重新查找、导入和选定；确认新的选择会替换停用标记。

### 播放时自动补缺

`设置 → 曲库` 中分别开启自动获取封面、自动获取歌词。两个选项默认关闭，首次使用由用户确认联网范围；它们与软件启动更新检查分别保存。新增“自动补全也使用 QQ、网易云与 Deezer”独立开关默认关闭，已有用户可以明确扩大自动联网范围。

开始播放后，等曲目稳定约 1.5 秒，再检查缺失项。已有本地封面、歌词或选定资料继续使用。连续切歌取消过时网络任务；旧曲目的迟到结果通过请求代次和资料身份隔离。暂停恢复的会话首先显示已保存资料，实际播放后才考虑自动请求。

高置信且唯一的候选可以自动使用。多个匹配版本留待手动选择，网络失败保留已有内容。用户可随时从歌曲菜单重新检索；自动失败不会进入音频错误通道。

### 批量补全

`曲库更多 → 补全缺失资料…` 可处理当前详情页或整个曲库，选择缺失歌词或缺失封面。文件检查在后台进行；专辑封面按专辑身份去重，已有选定资料在准备阶段排除。

单批最多 5,000 项。更大的曲库可以按详情页分批整理；批次上限用于限制内存和公共服务请求规模。每完成一项就保存进度，列表显示最近 200 项结果；需要选择、未找到或失败的行可以打开手动检索。已处理内容长期保留。

暂停保留剩余任务；取消项单独计数并支持“重试未完成项”；退出再打开后，持久化任务以暂停状态恢复。单来源返回 429 / 503 时遵守 Retry-After，最多自动重试两次；多来源查询保留健康来源结果，跳过暂时失败的来源。失败结果可重新查询，已选定资料继续保留。批次保存本次来源选择。手动查找优先于批量任务。

## 本地优先与资源身份

歌曲绑定键使用路径的 SHA-256，另外保存路径和关键音乐标签的身份摘要。mtime、音频属性的微小舍入变化保持绑定稳定；同一路径改成另一首歌时，关键标签身份会变化。

封面优先级为手动固定选择、本地资料、自动取得资料。有效的曲目级停用标记同时阻止继承专辑在线封面。未知专辑单曲之间保持独立。

歌词顺序为手动固定选择、现有同名歌词文件 / 内嵌歌词、自动取得的资料。支持的本地逐字文件优先于同名普通 LRC，损坏资料继续尝试下一来源。每份在线歌词使用独立内容摘要作为偏移键；更换或恢复本地歌词时采用对应偏移。源标记为纯音乐时单独展示来源与状态。原始字词时间、行时间与纯文本分别保存，当前界面统一使用整句高亮。

固定选择的文件缺失或损坏时，保留选择意图，界面回退到可用本地资料；手动窗口提示重新选取。自动请求会尊重该固定记录。内容读取校验 SHA-256、文件类型与大小，损坏资源进入可恢复状态。

## 匹配策略

LRCLIB 查询按歌曲和艺术家检索，再结合专辑、时长、版本标记排序。自动使用要求歌名与艺术家归一化后相同、时长差在两秒内、版本标记相容，并符合已知专辑信息。展示列表在排序后截取前 20 项；超过受限候选范围时采用保守的人工确认策略。

大小写、全半角和常见标点可以归一化。Live、Remix、Acoustic、Instrumental、TV Size、Radio Edit、Extended、Remaster 等标记单独参与版本判断。上述规则属于确定性过滤，实际匹配质量仍通过音乐样本验收。

MusicBrainz 优先查询发行版本；专辑信息缺失时可以从录音候选中寻找发行版本。自动封面要求唯一、专辑/艺术家精确匹配且为兼容的官方发行版本。封面取正面 `front-1200`。具体发行版本缺图时，手动预览可尝试发行组，并明确标注“发行组封面”，保留对应来源 ID 和页面。

原有 LRCLIB、MusicBrainz / Cover Art Archive 继续保留。新增 QQ 音乐、网易云音乐和 Deezer 独立适配器；查询使用公开元数据入口和普通请求头，无需用户账号。第三方服务的接口、地区限制与内容使用条件可能变化，覆盖率和误配率需持续样本测试。具体查询策略与维护边界见 [MULTISOURCE_AND_COPY.md](MULTISOURCE_AND_COPY.md)。

## 存储与资源管理

持久目录：

```text
${XDG_DATA_HOME:-$HOME/.local/share}/liusheng/online-assets/
  bindings/    曲目/专辑绑定、来源、固定选择与停用记录
  objects/     内容寻址 JPEG 和 UTF-8 LRC
  search/      可过期的检索结果
  previews/    可清理的封面预览
  batch.json   剩余任务与最近处理结果
  cooldowns.json  来源等待期限
```

目录仅当前用户可读写，文件使用原子替换。音乐文件、内嵌标签和音乐目录保持原样；清理搜索缓存只处理 `search/` 与 `previews/`，固定选择与已保存资源继续保留。

普通结果缓存一天，未找到的查询缓存七天。手动“搜索”可以刷新检索结果，同时继续遵守来源限流。搜索与预览缓存按年龄和约 128 MiB 配额定期裁剪；已选定的资源属于持久应用数据。

## 网络、性能与跨平台

生产来源固定为 HTTPS，保留证书验证。QNetworkAccessManager、JSON 处理、图片解码与文件写入都在独立事件线程运行；GUI 接收状态和本地资源路径。网络服务按首次需求创建，启动阶段的缓存曲库和首帧继续走原有路径。

单次仅一个网络请求，手动请求优先，MusicBrainz 调用至少间隔 1.3 秒。请求包含应用 User-Agent，采用手动重定向策略；图片重定向允许 Cover Art Archive / archive.org 和新增来源的固定 CDN 路径，所有跳转继续验证 HTTPS、主机、端口和资源类型。元数据响应上限 2 MiB，图片 8 MiB；传输空闲上限 8 秒，总请求期限 15 秒。来源限流期限有上限并持久化。

图片先核对格式与尺寸，再生成最长边 1,200px 的 JPEG 和主题色。歌词沿用 1 MiB、10,000 行、单行 8 KiB、展开文本 2 MiB 的解析限制。外部文本以纯文本展示。在线图片请求声明 JPEG / PNG，避免缺少 WebP 插件时由内容协商触发解码错误。

请求只使用必要音乐元数据；本地路径和身份摘要用于本机绑定，音频、目录清单、播放队列和账号凭据保持在本机。设置界面提供独立同意开关。`--no-online-metadata` 对本次运行关闭音乐资料联网；手动导入和已有离线资料继续工作。

候选窗口、确认框使用 `Popup.Item`，文件选择器指定父窗口。异步结果保持用户焦点；封面更新发送本地文件 URL，经现有通道同步至 Qt 页面、MPRIS 与 macOS MediaPlayer。界面更新只影响相关资料，音频输出后端、解码与重采样保持原实现。

## 测试与验收

```sh
just online-assets-test
python3 scripts/check-online-assets.py --compiler clang --output target/qa/online-assets/clang
python3 scripts/check-controls.py
python3 scripts/check-ui.py target/release/liusheng --output target/qa/online-assets/ui
python3 scripts/check-wayland.py target/release/liusheng --output target/qa/online-assets/wayland
# 显式联网验证：固定公开中英文样本，临时资源目录
python3 scripts/check-online-assets.py --live
```

常规 CI 使用本地 HTTP 服务，覆盖版本歧义、排序、请求取消、限流、重定向、响应容量、资源损坏、手动固定、清理、离线重启和批次恢复。测试宏中的地址注入只用于独立测试可执行文件；生产程序保持固定来源。

Rust 回归检查身份、来源优先级、解析器、偏移和隐私默认值。实际 GUI 回归进一步执行导入 → C++ 持久化 → Rust 读取 → 页面刷新 → 恢复默认，并检查未知专辑隔离与设置保存/取消。

Linux 和 Apple Silicon 的共享质量工作流均包含原生 C++ 测试。AppImage 继续执行实际打包、迁移启动、完整界面和 Wayland 三档回归。macOS 的原生编译/运行、系统控制中心与物理耳机按键，分别通过原生 CI 与实机验收。

在线功能初次收尾验证的具体结果、源码与产物校验值记录于 `target/qa/online-assets/recheck/final/`，汇总索引为 `target/qa/online-assets/recheck/summary.json`。此前的 `target/qa/online-assets/final/` 保留了修正前的失败日志，用于追溯。实时来源复核记录分别保存在 `recheck/live.log` 与 `recheck/live-second.log`；前次封面来源返回暂时不可用，后次歌词检索与封面下载预览全部完成。公开样本用于验证链路，实际曲库覆盖率保持独立验收。

最新多来源与文案精简的完整验收见 `target/qa/multisource-refinement/summary.json`。
